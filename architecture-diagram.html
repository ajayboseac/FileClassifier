⚙ System Architecture

FileClassifier Pipeline

An automated Google Apps Script system that classifies health insurance documents using Gemini AI vision & text analysis, then organizes them into structured claim folders on Google Drive.

Google Apps Script Gemini 2.0 Flash Google Drive API Vision AI Google Sheets

File Preparation
👁️

Vision Path (Preferred)

Images & PDFs are converted to base64 and sent directly to Gemini Vision for analysis. Supports JPEG, PNG, GIF, BMP, WebP, TIFF, and PDF.

≤ 15 MB limit
prepareFileForLLM() → vision
📝

Text Extraction

Google Docs and plain text files have their content extracted directly via DocumentApp or getBlob().getDataAsString().

≥ 10 chars required
prepareFileForLLM() → text
🔍

OCR Fallback

For unsupported types or large files, uses Google Drive's OCR to create a temporary Google Doc, extract text, then delete the temp doc.

Drive.Files.copy()
prepareViaOCR()

3
AI Classification
🤖

Gemini API Call

Sends document with a detailed classification prompt to Gemini 2.0 Flash. Includes category definitions, disambiguation rules, and output format spec. Uses temperature: 0.1 for consistency and response_mime_type: application/json for structured output.

generateContent API
callLLM() → buildClassificationPrompt()

12 Document Categories:

Prescription Consultation Bill Medicine Bill Pharmacy Receipt Diagnostics Bill Lab Report Radiology Report Discharge Summary Hospital Bill Insurance Form Doctor Notes Other
✅

Parse & Validate Response

Parses the JSON response and validates the category against the allowed list. Invalid categories default to "Other". Patient names are cleaned of titles (Dr., Mr., Mrs., etc.). Date format is validated as YYYY-MM-DD.

parseAndValidateLLMResponse()

Extracted Metadata Fields:

category documentDate patientName clinicName billNumber amount doctorName notes

4
Claim Matching

Does an existing claim folder match?

Fuzzy name matching (token overlap + Levenshtein distance, ≥70% similarity) within a 14-day date window

✓ Match Found
🔗

Assign Existing Claim

File is linked to the matched claim folder. The existing folder's name (e.g. AjayBose_2025-03-15) is used.

findMatchingClaim()
✗ No Match
🆕

Create New Claim

A new claim folder name is generated: PatientName_YYYY-MM-DD. The new claim is added to the in-memory list for batch matching.

generateClaimName()
🔤

Name Normalization

Strips titles (Dr/Mr/Mrs/Ms), removes special chars, lowercases, and trims whitespace for consistent comparison.

normalizeName()
📊

Token Similarity

Splits names into tokens. Scores exact matches (1.0), substring matches (0.7), and Levenshtein-close matches (0.8). Handles OCR errors and abbreviations.

calculateNameSimilarity()
📏

Levenshtein Distance

Edit-distance algorithm for fuzzy matching. Allows up to ~30% character difference per token to handle OCR typos and spelling variations.

levenshteinDistance()

Reporting & Audit
📊

Consolidated Report

A Google Sheet is created (or updated) per claim folder. Appends a row with patient name, clinic, doctor, bill number, category, amount, document date, date added, and notes.

Per-claim sheet
updateConsolidatedSheet()
📋

Classification Log

A central audit log in the root destination folder records every classification decision: timestamp, original filename, category, patient, clinic, amount, claim folder, and the raw LLM response for debugging.

Global audit trail
