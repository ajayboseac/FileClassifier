Prescription ↔ Document Matching
🔗

linkToPrescription() — Core Matching Engine

For each non-prescription document in the claim, attempts to match its items against prescribed items. The matching strategy depends on document category:

Document Category Matches Against Matching Function Strategy
💊 Medicine Bill prescribedItems (type: medicine) matchMedicines() Fuzzy name match ≥ 70%
🧪 Diagnostics Bill prescribedItems (type: test) matchTests() Fuzzy name match ≥ 70%
📊 Lab Report prescribedItems (type: test) matchTests() Fuzzy name match ≥ 70%
🩻 Radiology Report prescribedItems (type: test) matchTests() Fuzzy name match ≥ 70%
💳 Consultation Bill Any prescription matchByDate() Same date ± 1 day
linkToPrescription() → matchMedicines() / matchTests() / matchByDate()
💊

matchMedicines() — Fuzzy Medicine Matcher

For each item in billedItems, search across all prescriptions' prescribedItems (where type = "medicine"). Uses the existing calculateNameSimilarity() engine after normalizing drug names (strip strengths, lowercase).

Example:
Bill: "Amoxicillin 500mg" ↔ Rx: "Amoxicillin 500 mg"
✅ Amoxicillin → Matched ❌ Paracetamol → Not Prescribed
🧪

matchTests() — Fuzzy Test Matcher

For each item in billedItems or reportedTests, search across prescriptions' prescribedItems (where type = "test"). Handles abbreviations (CBC ↔ Complete Blood Count) via substring + Levenshtein matching.

Example:
Report: "CBC" ↔ Rx: "Complete Blood Count"
✅ CBC → Matched ⚠️ Lipid Panel → Not Prescribed

The item appears on a bill but is not found in any prescription. Insurance will likely reject this.
